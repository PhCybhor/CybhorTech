Problemas e dificuldades na criação

O que travou cada projeto e como foi resolvido. Serve de aprendizado para os próximos.

CybhorPDV

Lojas ainda usam Windows 7
Dificuldade: as versões novas do Electron não rodam no Windows 7, e boa parte dos caixas de mercado e padaria ainda usa esse sistema.
Solução: o app ficou no Electron 22, o último que roda no Windows 7, com um instalador só para Windows 7 a 11 em 32 e 64 bits.
Internet cai no meio da venda
Dificuldade: o caixa não pode parar quando a internet cai, mas as vendas precisam chegar à nuvem sem duplicar nem sumir.
Solução: fila de vendas offline gravada em disco (não no cache do navegador), que sobrevive a queda de energia e é enviada sozinha quando a conexão volta. Arquivo corrompido é separado em vez de apagado.
Troca de servidor no meio do projeto
Dificuldade: a API nasceu em Python (FastAPI) com PostgreSQL, mas a hospedagem escolhida (Hostinger) roda Node.js com MySQL.
Solução: a API foi reescrita em Node.js + MySQL, com script de migração dos dados do PostgreSQL. A versão antiga fica no repositório até a troca terminar.
Impressora térmica sem documentação moderna
Dificuldade: a Jetway JP-800 só tinha exemplo em Delphi, e imprimir pelo diálogo do Windows deixava o cupom lento e desalinhado.
Solução: impressão direta em ESC/POS, igual ao exemplo oficial, com detecção automática da impressora e um modo de teste que gera o cupom sem papel.
Várias lojas no mesmo banco
Dificuldade: uma loja nunca pode ver produtos ou vendas de outra, e cada loja pode ter vários caixas.
Solução: a loja vem sempre do login, nunca do pedido. Caixas novos entram com o código da loja.
Pagamento confirmado de verdade
Dificuldade: o aviso de pagamento do Mercado Pago pode chegar atrasado, repetido ou ser forjado.
Solução: a cada aviso o servidor consulta o pagamento direto no Mercado Pago antes de liberar o código da loja.

Luma

Um carrinho com produtos de várias lojas
Dificuldade: o cliente paga uma vez só, mas o dinheiro precisa ir para lojas diferentes, já descontando a comissão.
Solução: o pedido é dividido em subpedidos por loja e o valor de cada uma vai para uma carteira, liberada depois da confirmação.
Lojista falso ou com má reputação
Dificuldade: qualquer pessoa conseguia abrir uma loja.
Solução: validação de CNPJ, consulta de reputação pública e aprovação manual da loja no painel administrativo.
Banco mudando com o sistema no ar
Dificuldade: reputação, carteira, cadastro completo e moderação vieram depois do lançamento, com dados reais já gravados.
Solução: cinco migrações em sequência e checagens que criam as colunas que faltam ao iniciar, sem derrubar o site.
Admin separado da loja
Dificuldade: o painel administrativo não podia ficar acessível pelo endereço público do marketplace.
Solução: o servidor separa por domínio: o admin só abre no domínio próprio de operação.

Portal Cybhor

Hospedagem compartilhada não roda Docker
Dificuldade: a versão completa (Node.js, PostgreSQL, WebSocket e armazenamento S3) precisa de Docker, que a Hostinger compartilhada não oferece.
Solução: duas versões: uma em PHP + MySQL que roda na Hostinger hoje e outra completa em Docker para uma VPS.
Progresso de projeto "no chute"
Dificuldade: as pessoas digitavam a porcentagem dos projetos à mão, e o número não batia com o que estava pronto.
Solução: a porcentagem só sobe quando alguém envia o código do commit; a pontuação vem de tarefas entregues, não de horas.
Equipe achou complicado
Dificuldade: a primeira versão tinha módulos demais na tela inicial.
Solução: o início foi reduzido a três passos (Pessoas, Tarefas e Hoje) e o resto foi para o menu "Mais".

Sistema de Leads

Servidor dividido com outros sistemas
Dificuldade: a VPS já rodava outros projetos e um banco compartilhado, e no Docker as portas publicadas passam por cima do firewall.
Solução: rede Docker exclusiva para o banco, API publicada só para o próprio servidor e um deploy que se recusa a subir se encontrar o banco exposto.
Dados pessoais e LGPD
Dificuldade: leads são dados pessoais; quem pede para não ser contatado não pode voltar numa importação nova.
Solução: lista de supressão permanente, auditoria que a aplicação não consegue apagar e exportação CSV protegida contra fórmulas maliciosas.
Medo de perder dados num deploy
Dificuldade: uma migração com erro poderia estragar a base inteira.
Solução: backup automático antes de cada migração, rollback testado e backup diário cifrado fora do servidor.

Levantamento patrimonial e marca

Centenas de fotos fora de ordem
Dificuldade: o levantamento de TI/Saúde teve mais de 340 fotos, e montar o Word à mão levava dias e trocava foto de lugar.
Solução: um JSON liga cada bem à sua foto; o script monta a tabela e coloca uma foto por página, redimensionada, na mesma ordem.
Comunicação prometendo o produto errado
Dificuldade: os primeiros criativos falavam em "licença única", mas o CybhorPDV é assinatura mensal; e a identidade azul-escura parecia genérica.
Solução: regras de texto (só "assinatura", sempre "a partir de R$ 99,90/mês") e uma identidade nova tirada do próprio site do PDV.
